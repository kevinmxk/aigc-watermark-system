# StegaStamp 用户 ID 容错识别方案

> **版本**: v1.0 | **日期**: 2026-05-18 | **作者**: 大虾

---

## 一、问题分析

### 1.1 为什么 100 比特容易出错？

StegaStamp 的 Encoder-Decoder 是一个有损通道：
- **Encoder** 在像素空间嵌入水印 → 图像质量受 λ 参数影响
- **Decoder** 从图像中提取比特 → 受 JPEG 压缩、噪声、裁剪等干扰

实验数据（三层叠加实验结果）：

| 场景 | 比特准确率 | 错误比特数（100 比特中） |
|------|----------|----------------------|
| 理想（无攻击） | 99.4% ~ 100% | 0 ~ 0.6 |
| JPEG Q50 | 100% | 0 |
| JPEG Q30 | 99% | ~1 |
| 高斯噪声 σ=10 | 99% | ~1 |
| 裁剪 20% | 61% ~ 67% | ~33 ~ 39 |

### 1.2 精确匹配的致命缺陷

**旧方案**使用精确字符串匹配：100 个比特必须全部相同才算识别成功。

```python
# ❌ 旧方案：精确字符串匹配
def verify_old(decoded, expected):
    return np.array_equal(decoded, expected)  # 100 比特必须全对
```

| 图片 + 用户 | 比特准确率 | 错误比特 | 旧方案结果 |
|------------|----------|---------|----------|
| cat / USER005 | 97% | 3 | ❌ 失败 |
| cat / USER009 | 99% | 1 | ❌ 失败 |
| city / USER007 | 98% | 2 | ❌ 失败 |
| city / USER009 | 99% | 1 | ❌ 失败 |

**结论**：5 张图中有 3 张的至少一个用户 ID 会识别失败，即使比特准确率高达 97%~99%。

## 二、新方案：汉明距离 + 阈值匹配

### 2.1 核心思想

```python
# ✅ 新方案：汉明距离匹配
def verify_new(decoded, expected, max_hamming=10):
    hamming = int(np.sum(decoded != expected))  # 数错误的比特数
    return hamming <= max_hamming               # 错误不超过阈值即通过
```

**关键参数：`max_hamming = 10`**

含义：100 比特中最多允许 10 个错误（即比特准确率 ≥ 90%）即认为用户匹配。

### 2.2 为什么是 10？

| max_hamming | 要求准确率 | 覆盖场景 | 误判概率（单用户） |
|-------------|----------|---------|------------------|
| 0 | 100% | 仅理想情况 | 2^-100 |
| 3 | 97% | + JPEG Q30 | ~10^-25 |
| **10** | **90%** | **+ 噪声 σ=10** | **~10^-17** |
| 20 | 80% | + 裁剪 20%（部分） | ~10^-7 |
| 40 | 60% | + 裁剪 20% | ~0.5 |

选 10 的原因：
- 覆盖 97%~100% 准确率的所有正常使用场景
- 误判概率 2^-90 ≈ 10^-27（比中彩票还低 18 个数量级）
- 不会覆盖裁剪攻击（61%~67%，错误 33~39 比特），保持安全性

### 2.3 效果对比

| 图片 + 用户 | 旧方案 | 新方案 (max_hamming=10) |
|------------|--------|----------------------|
| cat / USER005 (97%, 3错误) | ❌ 失败 | ✅ 通过 |
| cat / USER009 (99%, 1错误) | ❌ 失败 | ✅ 通过 |
| city / USER007 (98%, 2错误) | ❌ 失败 | ✅ 通过 |
| city / USER009 (99%, 1错误) | ❌ 失败 | ✅ 通过 |
| 所有理想情况 (100%) | ✅ 通过 | ✅ 通过 |

## 三、完整验证流程

### 3.1 编码阶段

```
用户 ID (字符串) "user_001"
         ↓
   CRC32 编码 (4 字节) + UTF-8 字节
         ↓
   转为比特串 (填充到 100 bits)
         ↓
   StegaStamp Encoder → 水印图像
```

### 3.2 解码 + 验证阶段

```
水印图像
    ↓
StegaStamp Decoder → 100 比特（可能有错误）
    ↓
计算汉明距离 vs 期望用户的 100 比特
    ↓
hamming ≤ 10？
    ├── 是 → 用户匹配 ✅
    └── 否 → 用户不匹配 ❌
```

### 3.3 用户识别（未知用户场景）

当需要从已知用户列表中识别身份时，遍历所有已知用户，找汉明距离最小的：

```python
def identify_user(decoded_secret, known_users):
    best_user = None
    best_hamming = 101
    for user_id in known_users:
        expected = encode(user_id)
        hamming = sum(decoded_secret != expected)
        if hamming < best_hamming:
            best_hamming = hamming
            best_user = user_id
    if best_hamming <= 10:
        return best_user, 1.0 - best_hamming/100
    return None, 0  # 无匹配
```

## 四、安全性分析

### 4.1 误判率（陌生人被识别为某个用户）

假设攻击者随机生成 100 比特：
- 与某个特定用户的汉明距离服从 Binomial(100, 0.5)
- P(汉明距离 ≤ 10) = Σ C(100,k) × 0.5^100 (k=0~10) ≈ **2.6 × 10^-17**

如果有 N 个注册用户：
- P(被误认为某个用户) ≈ N × 2.6 × 10^-17
- 即使 N = 100 万：P ≈ 2.6 × 10^-11（仍然极低）

### 4.2 伪造攻击

攻击者要伪造某个用户的 StegaStamp 水印：
1. 需要知道该用户的 100 比特 secret
2. 需要训练 StegaStamp Encoder 或找到合适的注入方式
3. 即使注入，汉明距离仍需 ≤ 10

### 4.3 不同阈值的安全性

| max_hamming | 误判率 (100万用户) | 覆盖错误比特 |
|-------------|-------------------|------------|
| 5 | ~10^-25 | 95% 准确率 |
| **10** | **~10^-17** | **90% 准确率** |
| 15 | ~10^-11 | 85% 准确率 |
| 20 | ~10^-7 | 80% 准确率 |

**max_hamming=10 在实用性和安全性之间取得了良好平衡。**

## 五、可提升方向

### 方向 1：BCH 纠错码

当前方案是"检测 + 丢弃"，可升级为"检测 + 纠正"：

```
100 比特 = [16 比特用户 ID] + [84 比特 BCH 纠错码]
```

- BCH(100,16) 可以纠正最多 **14 个错误比特**
- 即使 JPEG Q30 + 噪声叠加（~2-3 比特错误），也能完美恢复
- 需要额外实现 BCH 编码/解码逻辑（可用 `bchlib` 库）

### 方向 2：双重验证（汉明距离 + CRC32）

```python
def verify_v2(decoded, expected_user_id):
    # 第一关：汉明距离
    hamming = sum(decoded != encode(expected_user_id))
    if hamming > 10:
        return False
    
    # 第二关：CRC32 校验
    crc_extracted = decode_crc(decoded[:32])
    crc_expected = zlib.crc32(expected_user_id.encode())
    return crc_extracted == crc_expected
```

双重验证更安全：汉明距离过滤大部分错误，CRC32 消除误判。

### 方向 3：动态阈值

```python
def adaptive_threshold(image_quality):
    if image_quality == 'ideal':
        return 3   # 理想情况严格
    elif image_quality == 'compressed':
        return 10  # 压缩放宽
    elif image_quality == 'cropped':
        return 30  # 裁剪大幅放宽
```

根据图像质量（PSNR/SSIM）动态调整阈值，兼顾严格性和鲁棒性。

### 方向 4：多数投票冗余编码

```
100 比特 = [33 比特 × 3 份] + [1 比特校验]
```

每份 33 比特存相同的用户 ID，解码时对 3 份做多数投票：
- 任何 1 份完全错误也能恢复
- 抗裁剪攻击能力更强（20% 裁剪只影响 1 份）

| 指标 | 旧方案（精确匹配） | 新方案（汉明距离） |
|------|------------------|------------------|
| 理想情况通过率 | 100% | 100% |
